# BrainStorm — Rust Server

High-performance rewrite of the BrainStorm quiz platform backend in Rust.

## Status

- ✅ Axum HTTP/WS server
- ✅ PostgreSQL with migrations
- ✅ Session-based auth (argon2id)
- ✅ Rate limiting
- ✅ CORS, tracing, error handling
- ✅ Room registry (in-memory)
- ✅ WebSocket gameplay: join / start / answer / scoring / server-side timer / play again
- ✅ Multi-provider AI (OpenRouter by default, OpenAI, GigaChat, Ollama) + offline fallback bank
- ✅ Frontend: separate SvelteKit project in `../frontend`

## Quick Start

### Prerequisites

- Rust 1.85+
- PostgreSQL 16 (`docker compose up -d postgres`)
- AI provider key (optional — the game works offline with the built-in question bank)

### Local Development

1. **Start Postgres and Redis**:
   ```bash
   docker compose up -d postgres redis
   ```

2. **Run migrations**:
   ```bash
   cargo install sqlx-cli
   sqlx migrate run --source migrations
   ```
   Or let the app run them automatically on startup.

3. **Configure environment** (a `.env` file in the repo root is loaded automatically):
   ```bash
   cp config/default.toml config/local.toml
   # Edit local.toml with your settings
   export BRAINSTORM_SECRET_KEY="your-secret-key-at-least-32-bytes"
   export BRAINSTORM_ADMIN_SECRET_KEY="your-admin-key"
   export OPENROUTER_API_KEY="sk-or-..."   # optional: enables AI question generation
   ```

4. **Run the server**:
   ```bash
   cargo run
   ```
   Server starts at `http://localhost:5000`.

5. **Health check**:
   ```bash
   curl http://localhost:5000/health
   curl http://localhost:5000/readyz
   ```

### Docker Deployment

```bash
docker compose up --build
```

Access the API at `http://localhost:5000`.

## API Endpoints

### Health
- `GET /health` — liveness probe
- `GET /readyz` — readiness probe (checks DB)

### Auth
- `POST /api/auth/register` — create account
- `POST /api/auth/login` — authenticate
- `POST /api/auth/logout` — end session
- `GET /api/auth/me` — current user

### Admin
- `POST /api/admin/activate` — activate admin mode
- `GET /api/admin/rooms` — list rooms
- `GET /api/admin/users` — list users
- `POST /api/admin/ban` — ban user/IP
- `POST /api/admin/unban` — remove ban
- `POST /api/admin/reset_user` — reset stats
- `GET /api/admin/audit_log` — view audit log

### Leaderboard
- `GET /api/leaderboard/top?limit=50` — top players
- `GET /api/leaderboard/rank/:username` — user rank

### Rooms
- `GET /api/rooms` — list public rooms
- `POST /api/rooms` — create room
- `GET /api/rooms/:code` — room details

### WebSocket
- `WS /ws` — real-time gameplay (auth via `brainstorm_session` cookie)

## AI providers

Questions are generated by the first enabled provider in `ai_providers`
(`config/default.toml`). A provider is enabled when it has an API key (Ollama
needs none). Keys are picked up from flat environment variables:

| Provider | Environment variable | Notes |
|----------|---------------------|-------|
| OpenRouter (default) | `OPENROUTER_API_KEY` | `openai/gpt-4o-mini`, `response_format: json_object` |
| OpenAI | `OPENAI_API_KEY` | `gpt-4o-mini` |
| GigaChat | `GIGACHAT_CREDENTIALS` | base64 `client_id:client_secret` |
| Ollama | `OLLAMA_HOST` | local, no key |

If no provider is available (or generation fails), `src/services/questions.rs`
supplies questions from a built-in bank, so a game always starts. Check the
active set with `GET /api/ai/providers`.

## WebSocket protocol

Both directions use `{"type": "...", "data": {...}}`.

Client → server:

| `type` | `data` | Allowed for |
|--------|--------|-------------|
| `join_room` | `{"code": "ABC123"}` | any authenticated user |
| `start_game` | `{}` | host only |
| `submit_answer` | `{"answer_index": 0}` | players in a running game |
| `play_again` | `{}` | host only |

Server → client:

| `type` | `data` |
|--------|--------|
| `room_joined` | `{"code", "topic", "is_host"}` |
| `players_updated` | `{"players": [{"name", "score", "is_host", "is_ready"}]}` |
| `question_emitted` | `{"index", "total", "time_limit", "question": {"question", "options", "time_limit"}}` |
| `question_result` | `{"correctIndex", "explanation"}` |
| `game_over` | `{"scores": [{"name", "score"}]}` |
| `error` | `{"message"}` |

Flow: `start_game` → `question_emitted` (timer starts) → answers → when everyone
answered or the timer expires → `question_result` → 5 s pause → next
`question_emitted` → `game_over` after the last question. The timer is
server-side, so a disconnected or idle player cannot stall the game.

## Configuration

All settings can be configured via environment variables (prefixed `BRAINSTORM_`) or `config/default.toml`.

**Critical production settings**:
- `BRAINSTORM_ENV=production` — enables strict validation
- `BRAINSTORM_SECRET_KEY` — ≥32 bytes, not the dev default
- `BRAINSTORM_ADMIN_SECRET_KEY` — required in production
- `BRAINSTORM_SESSION_COOKIE_SECURE=true` — required in production
- `BRAINSTORM_CORS_ORIGINS` — explicit list, no `*` in production

See `config/default.toml` for all options.

## Security

### Implemented
- ✅ Argon2id password hashing
- ✅ Session tokens in secure, httpOnly cookies
- ✅ Constant-time string comparison
- ✅ HMAC for rejoin tokens (scaffolded)
- ✅ Rate limiting (per-IP token bucket)
- ✅ CORS allowlist
- ✅ Audit log for admin actions
- ✅ Input validation (validator crate)
- ✅ SQL injection prevention (sqlx bind parameters)

### TODO
- ⏳ CSRF tokens for state-changing endpoints
- ⏳ Rejoin token verification
- ⏳ IP-based bans in WebSocket layer
- ⏳ Tester mode with explicit grant (not global code)

## Performance Targets

- p50 HTTP latency: <30ms
- p99 HTTP latency: <200ms
- WebSocket broadcast (100 players): <50ms
- Concurrent connections: 1000+
- Memory footprint: <100MB (idle)

## Architecture

```
src/
├── main.rs              # Entry point, server bootstrap
├── config.rs            # Configuration loading & validation
├── error.rs             # Error types (thiserror)
├── db.rs                # Postgres pool, migrations
├── security.rs          # HMAC, constant-time utils
├── domain/              # Core models (Room, Player)
│   ├── room.rs          # Room state machine, registry
│   └── player.rs        # Player model
├── services/            # Business logic
│   ├── accounts.rs      # User management
│   ├── ai/              # Provider router, cache, quota
│   │   └── providers/   # openrouter.rs, openai.rs, gigachat.rs, ollama.rs
│   ├── questions.rs     # Offline fallback question bank
│   ├── audit.rs         # Audit log
│   └── leaderboard.rs   # Ranking aggregates
├── middleware/          # HTTP middleware
│   ├── auth.rs          # Session validation
│   ├── cors.rs          # CORS layer
│   └── rate_limit.rs    # Token bucket
├── routes/              # HTTP handlers
│   ├── admin.rs         # Admin endpoints
│   ├── auth.rs          # Auth endpoints
│   ├── health.rs        # Health probes
│   ├── leaderboard.rs   # Ranking endpoints
│   └── rooms.rs         # Room CRUD
└── ws/                  # WebSocket handler
    └── mod.rs           # WS gameplay loop, server-side timer

migrations/
└── 20240101000001_initial.sql  # Database schema
```

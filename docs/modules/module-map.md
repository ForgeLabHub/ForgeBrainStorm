# Карта модулей: что заимствовать в другой проект

Приложение уже разделено на слои. Таблица отвечает на вопрос «что взять, если нужно X».

| Нужно | Взять файлы | Внешние зависимости | Заменить |
| --- | --- | --- | --- |
| Чистые правила игры и подсчёт очков | `app/domain/` | — | сам набор правил; держите слой без ввода-вывода |
| Комнаты, чат, планировщик раундов | `app/realtime/` | `flask-socketio` | транспорт и имена событий |
| Аккаунты, достижения, кампании | `app/services/` | — | таблицы в `app/user_db.py` |
| SQLite с WAL и идемпотентными миграциями | `app/db.py`, `app/user_db.py` | — | функции схемы |
| Опциональный AI с офлайн-режимом | `app/ai_client.py`, `app/services/ai_client.py` | `gigachat` | провайдер и промпты |
| Валидация входа и единый формат ошибок | `app/validation.py`, `app/errors.py` | — | каталог сообщений |
| Ограничение частоты запросов в процессе | `app/ratelimit.py` | — | лимиты по эндпоинтам |
| Health-эндпоинт с состоянием обеих баз | `app/http_api/health.py` | — | список баз |

## Правила переноса

1. Направление зависимостей фиксировано: `domain` → ничего, `services` → `domain` + `db`,
   `realtime`/`http_api` → `services`. Модуль, ломающий стрелку, нельзя забрать отдельно.
2. Глобального изменяемого состояния нет, кроме реестра комнат в памяти процесса: именно
   поэтому поддерживается один процесс.
3. Тесты — часть модуля: `domain` → `tests/test_domain.py`, `realtime` →
   `tests/test_realtime.py`, `tests/test_socket_flow.py`.
4. Конфигурация читается через один помощник, а не на импорте.

## Чего здесь нет

- Нет слоя `Repository`/ORM: два файла SQLite и явный SQL.
- Нет системы плагинов: сервисы импортируются напрямую, граф достаточно мал.

# Модуль: реальное время (комнаты, чат, планировщик)

## 1. Назначение и границы
Socket.IO-слой: подключение игроков к комнатам, синхронизация раундов, чат,
планировщик переходов между этапами.
Не делает: не содержит правил начисления очков (это домен); не хранит историю
комнат в БД, кроме агрегированной записи в лидерборде.

## 2. Сценарии использования
- Вход в комнату по коду, получение состояния.
- Старт раунда по таймеру; рассылка вопроса всем участникам.
- Чат комнаты; модерация админом.
- Отказ: комната заполнена/не существует → событие об ошибке.

## 3. Контракт
События `app/realtime/socket_events.py` и `app/realtime/chat.py`; HTTP-часть —
`app/http_api/rooms.py`. Список событий фиксируется в
[../api/conventions.md](../api/conventions.md).

## 4. Данные
Состояние комнат — в памяти процесса. В SQLite пишется только история завершённых
комнат (`leaderboard.db`).

## 5. Права
Ведущий комнаты имеет права на управление раундом; админ — на модерацию чата
(проверяется в `http_api/admin_routes.py`).

## 6. Зависимости
Исходящие: `game_logic`, `services.leaderboard`. Внешне — только транспорт
WebSocket. Входящие: клиент `static/js/game.js`.

## 7. Конфигурация
`SOCKETIO_ASYNC_MODE` (`eventlet`/`threading`), `PORT`, `HOST`. Планировщик
запускается вместе с приложением.

## 8. Сборка и отладка
```bash
python -m pytest tests/test_realtime.py tests/test_socket_flow.py -q
```

## 9. Тесты
`tests/test_realtime.py` (комнаты и рассылка), `tests/test_socket_flow.py`
(полный сценарий раунда), `tests/test_api.py` (HTTP-часть комнат).

## 10. Наблюдаемость
Логи подключений и ошибок комнат; дисконнекты — ключевой сигнал при жалобах на
«зависшую игру».

## 11. Ограничения и готовность
- Состояние в памяти: рестарт обрывает активные комнаты; несколько реплик не
  поддерживаются.
- Нет восстановления сессии игрока после обрыва связи.
- Готовность: сценарий раунда покрыт тестом; обрыв соединения не ломает другие комнаты.

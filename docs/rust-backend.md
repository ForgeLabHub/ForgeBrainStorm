# Rust-бэкенд: устройство и правила

Бэкенд — `rust-server/`, около 4 700 строк: axum 0.7 + tokio, sqlx/PostgreSQL,
собственный WebSocket-игровой цикл. Здесь описано, как он разрезан на слои и что
можно менять, не ломая остальное.

## Слои

```
main.rs        сборка приложения: конфиг, пул БД, миграции, роутер, слушатель
config.rs      Figment: default.toml → BRAINSTORM_* env
db.rs          PgPool, миграции, health-запрос
error.rs       AppError → HTTP-статус + JSON { error: { code, message } }
security.rs    сравнение секретов за постоянное время, подпись сессий
middleware/    auth (сессия), cors, rate_limit
routes/        HTTP: auth, rooms, ai, leaderboard, profile, admin, health
ws/            игровой цикл: join, start, question, answer, power-up, game_over
services/      I/O и внешние системы: accounts, history, leaderboard, audit,
               questions, ai/{providers, router, cache}
domain/        чистые правила без I/O: room, player, power_up, mode
```

Правило зависимостей — только вниз: `routes`/`ws` → `services` → `domain`.
`domain` не знает про HTTP, БД и таймеры tokio; всё, что требует времени или
сети, живёт в `ws/` или `services/`.

## Домен

- `Room` — код, состояние (`Waiting → Starting → Playing → Finished`), настройки,
  игроки, вопросы, текущий вопрос, `question_token` и дедлайн.
- `Player` — счёт, серия, жизни, команда, рука усилений, `outbox` для приватных
  событий и `award(correct, mode, speed)`, который и начисляет очки.
- `GameMode` — все различия режимов ([game-modes.md](game-modes.md)).
- `PowerUp` — двойные очки, заморозка таймера, удаление двух вариантов.

`RoomSettings::clamp()` — единственное место, где настройки приводятся к
допустимому диапазону (5–30 вопросов, 2–6 вариантов, 10–120 с, тема ≤ 200
символов). Он же применяет принудительный таймер режима, поэтому клиент не может
обойти правило блица.

## Игровой цикл (`ws/`)

1. `join_room` — авторизация по cookie, поиск комнаты, посадка игрока.
   Повторный коннект с тем же аккаунтом переносит счёт, а не плодит дубль.
2. `start_game` — только хост. Генерация вопросов (с кэшем), рассадка команд,
   выдача жизней, `reset_for_new_game` для каждого игрока.
3. `question_emitted` — вопрос без правильного ответа и без чужих вариантов;
   дедлайн хранится на сервере, клиент получает `time_limit`.
4. `submit_answer` — принимается один раз, считается `speed` по дедлайну,
   начисляются очки, обновляется серия и жизни.
5. `reveal_and_advance` — идемпотентен по `question_token`: устаревший таймер
   или дублирующий вызов просто выходят. Здесь же решается, закончилась ли игра
   (кончились вопросы или все выбыли в `lives`).
6. `game_over` — итоговая таблица, счёт команд, `persisted`; запись в БД
   запускается отдельной задачей, чтобы не держать сокет.

Приватные события (рука усилений, скрытые варианты) уходят в `Player::outbox`
конкретному сокету; broadcast видят все, поэтому туда такие данные не попадают.

## ИИ-провайдеры (`services/ai`)

`router.rs` держит список провайдеров в порядке приоритета и переключается на
следующий при ошибке или таймауте. Провайдеры — `providers/*`: `openai.rs`
обслуживает и OpenRouter (свой `base_url`), и OpenAI, рядом `gigachat.rs` и
`ollama.rs`; когда не ответил никто, `services/questions.rs` отдаёт офлайн-банк.
`cache.rs` кэширует наборы вопросов по
тема+сложность+количество, поэтому повторная игра по той же теме не тратит
токены. Без ключей работает офлайн-банк: приложение остаётся играбельным.

## Ошибки и наблюдаемость

- Любая ошибка возвращается как `{"error":{"code":"...","message":"..."}}`;
  `AppError` сам знает свой статус. Внутренние детали в ответ не попадают.
- Логи — `tracing` в JSON, фильтр `RUST_LOG`; в сообщениях есть латентность
  генерации, число вопросов, провайдер.
- `/health` — liveness, `/readyz` — проверка БД.

## Как расширять

| Задача | Куда идти |
|---|---|
| Новый режим | `domain/mode.rs` + подписи в UI ([game-modes.md](game-modes.md)) |
| Новый эндпоинт | `routes/<тема>.rs`, регистрация в `routes/mod.rs` |
| Новое WS-сообщение | ветка в `ws/mod.rs`, событие для клиента, тест в `#[cfg(test)]` |
| Новый ИИ-провайдер | `services/ai/providers/`, регистрация в `router.rs` |
| Новое поле в БД | `migrations/`, затем `services/*` и `db.rs` |

## Правила, которые нельзя нарушать

1. `unwrap()` в продакшен-коде запрещён: `?`, `expect("причина")` или `AppError`.
2. Изменение правил игры — только через `domain`, не в обработчике сообщения.
3. В broadcast не должно быть приватных данных.
4. Новое поведение — новый тест в том же файле; тесты с живой БД помечаются
   `#[ignore]`.
5. `make agent-verify` (fmt → check → clippy `-D warnings` → test) должен быть
   зелёным до того, как задача считается сделанной.

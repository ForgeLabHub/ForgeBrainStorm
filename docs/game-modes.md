# Режимы игры

Источник истины — `rust-server/src/domain/mode.rs`. Любое расхождение между
этим документом и кодом считается багом документации; правило проверяется
юнит-тестами модуля и живым сценарием `scripts/e2e-modes.py`.

## Как устроено

Режим — это `GameMode`, а не строка. Всё, чем режимы отличаются, вынесено в
методы этого типа:

| Метод | Что решает |
|---|---|
| `lives()` | сколько жизней выдать (`Some(3)` только для `lives`) |
| `timer_override()` | фиксированный таймер (`Some(10)` для `blitz`) |
| `points(speed, streak)` | сколько очков даёт верный ответ |
| `is_team()` | нужна ли рассадка по командам |
| `persists()` | писать ли результат в рейтинг и историю |
| `title()`, `description()` | подписи для UI |

`ws/mod.rs` спрашивает режим, а не сравнивает строки, поэтому новый режим — это
один вариант enum плюс одна ветка в каждом методе.

## Общие правила

- Комната создаётся хостом: тема, сложность, режим, число вопросов (5–30),
  число вариантов (2–6), таймер (10–120 с).
- Вопросы генерирует ИИ-провайдер; при недоступности — офлайн-банк.
- Все игроки получают один и тот же вопрос одновременно, ответ принимается
  один раз и не меняется.
- `speed` — доля таймера, оставшаяся к моменту ответа: `1.0` — мгновенно,
  `0.0` — на последней секунде. Время ответа считает сервер.
- После вопроса — пауза 5 секунд с правильным ответом и пояснением.
- `game_over` приходит всем и содержит `mode`, `persisted` и итоговую таблицу.

## Режимы

### 🎯 Классика (`classic`)

Верный ответ — ровно 100 очков. Жизней нет, таймер из настроек комнаты.
Результат идёт в рейтинг, XP и историю.

### ⚔️ Каждый за себя (`ffa`)

Очки зависят от скорости:

```
points = round5(40 + 60 * speed)     # 40 … 100, шаг 5
```

Отвечать быстро выгодно, но ошибаться всё ещё бесплатно.

### ❤️ На выживание (`lives`)

Старт с тремя жизнями (`SURVIVAL_LIVES`). Неверный ответ отнимает одну жизнь и
приносит 0 очков; верный — 100 и жизнь не возвращает. На нуле жизней игрок
становится зрителем (`eliminated: true`), его ответы больше не принимаются.
Раунд заканчивается досрочно, если все выбыли, — вопросов больше не ждём.

### ⚡ Блиц (`blitz`)

Таймер жёстко 10 секунд независимо от настроек комнаты (`timer_override`).
Серия верных ответов растит множитель:

```
points = round(60 * min(1 + 0.25 * (streak - 1), 2))
```

Первая верная — 60, третья подряд — 90, с девятой и дальше — 120 (потолок ×2).
Ошибка сбрасывает серию в ноль.

### 👥 Команды (`team`)

При старте игроки рассаживаются по порядку входа: чётные — «Синие» (0),
нечётные — «Красные» (1), поэтому составы отличаются максимум на одного
человека. Очки личные, но побеждает команда с большей суммой; `game_over`
дополнительно приносит массив `teams` со счётом каждой стороны. Ничья
показывается как ничья, а не как победа первого игрока списка.

### 🎓 Тренировка (`sandbox`)

Без жизней, верный ответ — 50 очков, таймер из настроек. Главное отличие:
`persists()` возвращает `false`, поэтому результат не попадает ни в рейтинг, ни
в историю, ни в XP/монеты. В `game_over` приходит `persisted: false`, и UI
прямо говорит, что партия нерейтинговая.

## Краевые случаи

| Ситуация | Поведение |
|---|---|
| Неизвестный режим в `POST /api/rooms` | `422`, в сообщении перечислены допустимые значения |
| Алиасы (`survival`, `teams`, `practice`, `free_for_all`) | принимаются, приводятся к каноническому коду |
| Режим без команд | `team` у игроков сбрасывается в `null` при старте |
| Повторная игра в той же комнате | очки, серия и жизни сбрасываются, рука усилений выдаётся заново |
| Игрок отключился | считается «не отвечает», но не выбывает в `lives`, пока не кончатся жизни |
| Все игроки выбыли в `lives` | раунд завершается досрочно, `game_over` уходит сразу |

## Как добавить режим

1. Вариант в `GameMode` + ветки `as_str`, `title`, `description`, `points`.
2. Если нужен особый таймер или жизни — `timer_override`/`lives`.
3. Если режим не должен влиять на рейтинг — `persists()`.
4. Подпись в `frontend/src/lib/ui.ts` и список режимов в `routes/room/create`.
5. Юнит-тест в `mode.rs` и проверка в `scripts/e2e-modes.py`.

## Проверено

- `cargo test` — 6 тестов модуля режимов (парсинг, очки, множители, правила).
- `python scripts/e2e-modes.py` — живые партии в `team`, `lives`, `blitz`,
  `sandbox`: команды и их суммы, выбывание на нуле жизней, принудительные 10 с,
  отсутствие записи в статистику у тренировки.

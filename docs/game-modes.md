# Режимы игры

Источник истины — `rust-server/src/domain/mode.rs`. Любое расхождение между
этим документом и кодом считается багом документации; правило проверяется
юнит-тестами модуля и живым сценарием `scripts/e2e-modes.py`.

## Как устроено

Режим — это `GameMode`, а не строка. Всё, чем режимы отличаются, вынесено в
методы этого типа:

| Метод | Что решает |
|---|---|
| `lives()` | сколько жизней выдать (`Some(3)` для `lives`, `Some(1)` для `sudden`) |
| `timer_override()` | фиксированный таймер (`10` у `blitz`, `15` у `svoyaigra`, `20` у `sudden` и `marathon`) |
| `question_override()` | фиксированная длина раунда (`Some(30)` у `marathon`) |
| `points(speed, streak)` | сколько очков даёт верный ответ |
| `is_team()` | нужна ли рассадка по сторонам (`team`, `coop`) |
| `is_coop()` | одна общая сторона вместо двух команд |
| `persists()` | писать ли результат в рейтинг и историю |
| `title()`, `description()` | подписи для UI |

`ws/mod.rs` спрашивает режим, а не сравнивает строки, поэтому новый режим — это
один вариант enum плюс одна ветка в каждом методе.

## Общие правила

- Комната создаётся хостом: тема, сложность, режим, число вопросов (5–30),
  число вариантов (2–6), таймер (10–120 с).
- Вопросы генерирует ИИ-провайдер; при недоступности — офлайн-банк.
- Набор всегда дотягивается до запрошенного числа: если провайдер вернул
  меньше вопросов, недостающие берутся из офлайн-банка без повторов. Режимы с
  фиксированной длиной (`marathon`) поэтому действительно идут 30 вопросов.
- Все игроки получают один и тот же вопрос одновременно, ответ принимается
  один раз и не меняется.
- `speed` — доля таймера, оставшаяся к моменту ответа: `1.0` — мгновенно,
  `0.0` — на последней секунде. Время ответа считает сервер.
- После вопроса — пауза 5 секунд с правильным ответом и пояснением.
- `game_over` приходит всем и содержит `mode`, `persisted` и итоговую таблицу.

## Режимы

### 🎯 Классика (`classic`)

Верный ответ — ровно 100 очков. Жизней нет, таймер из настроек комнаты.
Результат идёт в рейтинг, XP и историю.

### ⚔️ Каждый за себя (`ffa`)

Очки зависят от скорости:

```
points = round5(40 + 60 * speed)     # 40 … 100, шаг 5
```

Отвечать быстро выгодно, но ошибаться всё ещё бесплатно.

### ❤️ На выживание (`lives`)

Старт с тремя жизнями (`SURVIVAL_LIVES`). Неверный ответ отнимает одну жизнь и
приносит 0 очков; верный — 100 и жизнь не возвращает. На нуле жизней игрок
становится зрителем (`eliminated: true`), его ответы больше не принимаются.
Раунд заканчивается досрочно, если все выбыли, — вопросов больше не ждём.

### ⚡ Блиц (`blitz`)

Таймер жёстко 10 секунд независимо от настроек комнаты (`timer_override`).
Серия верных ответов растит множитель:

```
points = round(60 * min(1 + 0.25 * (streak - 1), 2))
```

Первая верная — 60, третья подряд — 90, с девятой и дальше — 120 (потолок ×2).
Ошибка сбрасывает серию в ноль.

### 👥 Команды (`team`)

При старте игроки рассаживаются по порядку входа: чётные — «Синие» (0),
нечётные — «Красные» (1), поэтому составы отличаются максимум на одного
человека. Очки личные, но побеждает команда с большей суммой; `game_over`
дополнительно приносит массив `teams` со счётом каждой стороны. Ничья
показывается как ничья, а не как победа первого игрока списка.

### 🎓 Тренировка (`sandbox`)

Без жизней, верный ответ — 50 очков, таймер из настроек. Главное отличие:
`persists()` возвращает `false`, поэтому результат не попадает ни в рейтинг, ни
в историю, ни в XP/монеты. В `game_over` приходит `persisted: false`, и UI
прямо говорит, что партия нерейтинговая.

### 🤝 Кооператив (`coop`)

Командный режим с одной стороной: `is_team()` истинно, но `is_coop()` сажает
всех на сторону 0, поэтому `game_over` приносит не две команды, а одну запись
`{"team": 0, "name": "Все вместе", "score": <сумма>}`. Личные очки считаются по
той же формуле, что и в командах, а серия верных ответов растит множитель:

```
points = round(50 * (1 + 0.1 * (streak - 1)))   # 50, 55, 60 … без потолка
```

Никто не выбывает: жизней нет, ошибка просто не приносит очков. Результат идёт
в рейтинг, как в командном режиме.

### 📺 Своя Игра (`svoyaigra`)

Быстрый раунд с жёстким таймером 15 секунд (`timer_override`). Очки растут с
ответом и округляются до десятков:

```
points = round10(60 + 40 * speed)     # 60 … 100, шаг 10
```

Категорий, ставок и выбора вопроса пока нет: это честная скоростная вариация,
а не полноценная «Своя Игра». Доска с темами, рядами и ставками — отдельная
задача, режим к ней не притворяется.

### 💀 Внезапная смерть (`sudden`)

Одна жизнь (`lives()` → `Some(1)`), жёсткий таймер 20 секунд. Любая ошибка
выбивает из игры сразу, зато верный ответ платит по удвоенной шкале «каждый за
себя»:

```
points = round5(120 + 80 * speed)     # 120 … 200, шаг 5
```

Раунд заканчивается, когда выбыли все, — оставшиеся вопросы не задаются.

### 🏃 Марафон (`marathon`)

Фиксированная длина: 30 вопросов независимо от настроек комнаты
(`question_override`), таймер 20 секунд. Очки растут с каждой серией верных
ответов и упираются в потолок:

```
points = 50 + min(10 * (streak - 1), 50)     # 50, 60, 70 … 100
```

Ошибка сбрасывает серию, но не выбивает из игры: марафон про выносливость, а не
про выбывание.

## Краевые случаи

| Ситуация | Поведение |
|---|---|
| Неизвестный режим в `POST /api/rooms` | `422`, в сообщении перечислены допустимые значения |
| Алиасы (`survival`, `teams`, `practice`, `free_for_all`, `cooperative`, `jeopardy`) | принимаются, приводятся к каноническому коду |
| Режим без команд | `team` у игроков сбрасывается в `null` при старте |
| Повторная игра в той же комнате | очки, серия и жизни сбрасываются, рука усилений выдаётся заново |
| Игрок отключился | считается «не отвечает», но не выбывает в `lives`, пока не кончатся жизни |
| Все игроки выбыли в `lives` или `sudden` | раунд завершается досрочно, `game_over` уходит сразу |
| Провайдер вернул меньше вопросов, чем просили | набор добирается из офлайн-банка без повторов |
| Аккаунт с ролью `cheater` | получает приватный бюджет способностей, см. `docs/rust-backend.md` |

## Как добавить режим

1. Вариант в `GameMode` + ветки `as_str`, `title`, `description`, `points`.
2. Если нужен особый таймер или жизни — `timer_override`/`lives`.
3. Если режим не должен влиять на рейтинг — `persists()`.
4. Подпись в `frontend/src/lib/ui.ts` и список режимов в `routes/room/create`
   (если у режима свой таймер или длина — добавь его в `FIXED_TIMERS` и
   `countLocked`).
5. Юнит-тест в `mode.rs` и проверка в `scripts/e2e-modes.py`.

## Проверено

- `cargo test` — юнит-тесты модуля режимов: парсинг и алиасы, очки по скорости и
  серии, множители, правила выбывания и записи в рейтинг.
- `python scripts/e2e-modes.py` — живые партии во всех режимах: `team` (две
  стороны и суммы), `lives` (выбывание на нуле жизней), `blitz` (принудительные
  10 с), `sandbox` (нет записи в статистику), `coop` (одна общая сторона и общий
  счёт), `svoyaigra` (принудительные 15 с и начисление очков).
- Живая проверка `sudden` и `marathon` (20 с, 30 вопросов, выбывание за ошибку)
  выполнялась вручную по WebSocket-протоколу; юнит-тесты `mode.rs` покрывают
  формулы очков, жизни и фиксированную длину.

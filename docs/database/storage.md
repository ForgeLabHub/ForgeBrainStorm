# Хранение данных

Две SQLite-базы в `DATA_DIR` (по умолчанию `/app/data` в контейнере):

| Файл | Назначение | Кто пишет |
| --- | --- | --- |
| `leaderboard.db` | анонимные игровые данные: лидерборд, баны, история комнат | `app/db.py` |
| `user_data.db` | аккаунты: пользователи, UGC-вопросы, прогресс кампаний, достижения | `app/user_db.py` |

## Правила

1. **WAL-журналирование.** Соединения короткие, создаются на запрос: объекты SQLite
   нельзя делить между eventlet-гринтредами.
2. **Схема создаётся идемпотентно** через интроспекцию `PRAGMA table_info`, а не
   `ALTER TABLE ... except: pass`. Повторный старт ничего не меняет.
3. **Две базы разделены осознанно:** анонимная игра не должна требовать аккаунта, а
   данные аккаунтов не должны смешиваться с игровыми.
4. **Никаких внешних СУБД.** Заявленная граница — один процесс + SQLite; переход на
   PostgreSQL — отдельное решение, а не «настройка».

## Резервное копирование

```bash
# файлы лежат в томе brainstorm-data
docker run --rm -v brainstorm-data:/data -v "$PWD/backups:/backups" alpine \
  tar czf /backups/brainstorm-$(date -u +%Y%m%dT%H%M%SZ).tar.gz -C /data .
```

Восстановление: остановить контейнер, распаковать архив в том, запустить, проверить
`/health` (он сообщает состояние обеих баз).

## Проверка

| Утверждение | Как проверяется |
| --- | --- |
| Схема создаётся на пустом каталоге | `tests/conftest.py` использует временный `DATA_DIR` для каждого прогона |
| Повторная инициализация безопасна | старт приложения в CI, затем повторный старт контейнера |
| Данные переживают рестарт | том `brainstorm-data` + `/health` после `docker compose restart` |

# ADR-0001: Cargo workspace as the project skeleton

- **Статус**: accepted
- **Дата**: 2026-11-27
- **PR**: `refactor/workspace-skeleton` (PR-1.1)

## Контекст

Бэкенд — один крейт `brainstorm` (~6 000 строк) в каталоге `rust-server/`.
Внутри него лежат три вещи с разными жизненными циклами и разными требованиями
к зависимостям:

1. чистая игровая логика (`domain/`) — ей не нужны tokio, axum и sqlx;
2. HTTP/WS-слой и инфраструктура (`routes/`, `ws/`, `middleware/`, `config.rs`);
3. AI-провайдеры (`services/ai/`) — сеть, кэш, свой конфиг.

Пока это один крейт, ничто не мешает `domain` импортировать `sqlx`, а тесты
логики тянут за собой весь сервер. Кроме того, формат WS-сообщений существует в
двух копиях (Rust `serde_json::json!` и TypeScript на клиенте), и расхождение
ловится только руками.

## Решение

1. Репозиторий становится Cargo-workspace: `crates/*` + `xtask`.
   Первый шаг — механический перенос без изменения кода: `rust-server/` →
   `crates/server/`.
2. Общие зависимости объявляются в `[workspace.dependencies]`; крейты
   наследуют их через `dep.workspace = true`.
3. Toolchain фиксируется в `rust-toolchain.toml` (один источник истины для
   rustup и CI), CI дополнительно сверяет версию из файла с установленной.
4. `cargo xtask` — те же проверки, что в CI (`fmt --check`, `clippy -D warnings`,
   `test`), чтобы локальный прогон и пайплайн не расходились.

## Следствия

- `cargo build --workspace`, `cargo test --workspace`, `cargo clippy --workspace
  -- -D warnings` — единственные команды, которые имеет смысл гонять.
- Артефакты сборки переезжают из `rust-server/target/` в `target/` в корне
  (обновлены `.gitignore`, скрипты, Makefile, CI, Dockerfile).
- Docker-образ теперь собирается из корня репозитория
  (`docker build -f crates/server/Dockerfile .`), потому что манифест крейта
  зависит от корневого `Cargo.toml` и `Cargo.lock`.
- Следующие шаги (protocol, domain, storage, ai) добавляют крейты, не меняя
  поведение сервера.

## Найденная проблема: MSRV был заявлен неверно

`Cargo.toml` объявлял `rust-version = "1.85"`, но `Cargo.lock` уже требовал
более новый компилятор: `uuid 1.29.3` → 1.89, `icu_* 2.4.0` и `time 0.3.55` →
1.88. Сборка на 1.85 падала на этапе разрешения зависимостей, то есть
заявленный минимум был ложью, а CI это не ловил, потому что ставил `stable`.

Решение: `rust-version = "1.89"` в `[workspace.package]` и
`channel = "1.89.0"` в `rust-toolchain.toml`. Проверено `cargo metadata`
(максимальный `rust_version` в графе) и полной сборкой на 1.89.0.

Альтернатива — откатить `uuid` и `icu` до версий, собирающихся на 1.85 — не
выбрана: она даёт ноль пользы пользователям и требует ручного сопровождения
lockfile.

## Альтернативы

| Вариант | Почему нет |
| --- | --- |
| Оставить один крейт, разделить модулями | Нет границы, которую проверяет компилятор; `domain` продолжит тянуть sqlx |
| Отдельные репозитории на крейт | Ломает атомарные изменения и CI, версионирование ради версионирования |
| Workspace без `xtask` | Проверки дублируются в CI, Makefile и docs; расхождения неизбежны |
| Зафиксировать `stable` вместо версии | Не воспроизводимо: «зелено вчера, красно сегодня» без изменений в коде |

# Verification matrix

English version of [../../verification/matrix.md](../../verification/matrix.md).

| Check | What it proves | Command | CI |
| --- | --- | --- | --- |
| Tests (190) | game rules, API, realtime, security | `make test` | `ci.yml` → `backend` |
| ruff | static rules are respected | `make lint` | `ci.yml` → `backend` |
| The app starts without AI | GigaChat is an option, not a requirement | start + `GET /health` | `ci.yml` → `backend` |
| Dependencies are pinned | a rebuild gives the same versions | `make install` from `requirements.lock.txt` | `ci.yml` → `backend` |
| The image builds and is healthy | the container starts and answers | `make build-image` + `/health` | `ci.yml` → `docker` |
| No secrets in the repository | keys do not leak through commits | `gitleaks` | `ci.yml` → `secrets` |
| `.env` is not tracked by git | the incident cannot repeat | `make doctor` | `ci.yml` → `secrets` + locally |
| Documentation is consistent | links are alive, module specifications are complete, every document has a translation and a PDF | `make docs-check` | `ci.yml` → `docs` |
| Compose fails without secrets | the production configuration cannot be empty | `docker compose config` | locally/manually |
| Smoke test of a live instance | the service answers after deployment | `make smoke-test` | manually after deploy |

## What is not checked automatically

- Several replicas: room state lives in process memory — the scenario is not supported
  rather than "not tested".
- Load and WebSocket stability with many players.
- The quality of questions generated by GigaChat.
- Restoring data from a backup: the procedure is described in
  [database/storage.md](../database/storage.md) but not automated (there is no database
  service that can be started in CI with one command).

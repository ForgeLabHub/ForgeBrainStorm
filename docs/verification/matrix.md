# Матрица проверок

| Проверка | Что доказывает | Команда | CI |
| --- | --- | --- | --- |
| Тесты (190) | правила игры, API, реальное время, безопасность | `make test` | `ci.yml` → `backend` |
| ruff | статические правила соблюдены | `make lint` | `ci.yml` → `backend` |
| Приложение стартует без AI | GigaChat — опция, а не условие | старт + `GET /health` | `ci.yml` → `backend` |
| Зависимости закреплены | повторная сборка даёт те же версии | `make install` из `requirements.lock.txt` | `ci.yml` → `backend` |
| Образ собирается и здоров | контейнер запускается и отвечает | `make build-image` + `/health` | `ci.yml` → `docker` |
| Секретов в репозитории нет | ключи не утекают через коммиты | `gitleaks` | `ci.yml` → `secrets` |
| `.env` не отслеживается git | инцидент не повторится | `make doctor` | `ci.yml` → `secrets` + локально |
| Документация согласована | ссылки живые, спецификации модулей полны | `make docs-check` | `ci.yml` → `docs` |
| Compose падает без секретов | прод-конфигурация не может быть пустой | `docker compose config` | локально/вручную |
| Smoke test живого инстанса | сервис отвечает после развёртывания | `make smoke-test` | вручную после деплоя |

## Что не проверяется автоматически

- Несколько реплик: состояние комнат живёт в памяти процесса — сценарий не
  поддерживается, а не «не протестирован».
- Нагрузка и стабильность WebSocket под большим числом игроков.
- Качество вопросов, сгенерированных GigaChat.
- Восстановление данных из копии: процедура описана в
  [database/storage.md](../database/storage.md), но не автоматизирована (нет сервиса
  БД, который можно поднять в CI одной командой).
